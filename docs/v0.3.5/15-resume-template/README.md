## 一、简历撰写核心原则

### 1.1 STAR 是对的，但大部分人在 R 上造假

判断标准一句话：**面试官能不能问出第三层？** 第一层"94% 是什么成功率"（口径）、第二层"怎么测的、样本多大"（脚本 + 用例集）、第三层"脚本给我看看 / 现在跑一遍"（可复现）。**凡是第三层会塌的数字，都不要写。**

真 R 与假 R 的差别就一条：真 R 有基线、有口径、有测量方法（"改前 11/62 错，改后 2/62，同一套 62 条用例"）；假 R 只有结论（"准确率提升到 94%"）。

### 1.2 六条硬规则

① **一页为佳**（应届 1 页、社招 1–2 页）② **每条经历都指向一个可指认物件**（仓库/PR/博客/线上系统）③ **动词开头、结果收尾** ④ **技术栈单独成行**（HR 与 ATS 都在找关键词）⑤ **不写"精通"** ⑥ **顺序服务岗位**（最相关项目放第一）。

### 1.3 AI Agent 方向简历的特殊性

| 特殊性 | 为什么 | 怎么写 |
|---|---|---|
| 源码级理解是稀缺信号 | 大部分人止步于调 API | 报得出类名 + 职责，如"`AgentLoop` 管回合、`AgentRunner` 管循环" |
| 协议理解比框架名值钱 | 框架会换，协议不会 | 写"MCP Server（stdio + streamableHttp）"，不写"熟悉 MCP 生态" |
| 端到端经验 > 单点能力 | 生产问题是跨层的 | 写"从渠道接入到工具执行的完整链路" |
| 失败经验是加分项 | 只有真跑过的人才有失败数据 | 写"哪一环最脆、怎么发现的" |

## 五、算法（LLM 应用）方向模板（模板 3）

**适用判断**：JD 出现"评测""效果""上下文策略""记忆""Prompt 优化""模型选型"，但**不要求**训练大模型。纯训练岗（SFT/RLHF/分布式）请另备一份，本章不覆盖。

```

项目周期：20XX.XX - 20XX.XX    项目角色：算法/应用（评测负责人）
技术栈：  Python、nanobot v0.3.5、<模型供应商>、<向量库>、pandas

项目描述：
在 nanobot 上搭一套可复现的评测流程：固定用例集 → 跑分 → 归因 →

核心职责：
• 自建 [占位: N] 条用例集（覆盖工具选择、多步任务、该放弃的任务），

  排序，给出分级路由方案（简单任务走便宜模型）
• 记忆侧只做读取优化：压缩产物是会话 checkpoint，长期事实由 Dream 低频
  更新，避免"每轮都改记忆"带来的抖动

项目成果：
• 用例集从 [占位] 扩到 [占位] 条，回归时间从 [占位] 分钟降到 [占位] 分钟
• 同一用例集成功率 [占位] → [占位]，单任务 token [占位] → [占位]
  （占位示例，不可直接投递；复跑命令见仓库 README）
• 产出一份选型报告，被采纳为团队默认 preset 配置
```

**项目经历句式**：**"用 X 度量 Y，发现 Z"**（先把度量立起来，再谈优化）；**"在 A 和 B 之间做对比实验，结论是 C，代价是 D"**（算法岗最认这个句式）；**"把 X 从 P 提到 Q（n=N）"**（有统计意识比有漂亮数字重要）。

**技术栈关键词**——必写：评测集设计、指标定义、Prompt 工程、上下文管理、模型选型；加分：成本归因、缓存命中、分级路由、A/B、可复现脚本；慎写：SFT/DPO/LoRA（没真跑过别写）、"论文复现"（会被问细节）。

## 十、简历注意事项

### 10.1 坏例子 vs 好例子（怎样写才经得起背调）

| 坏例子（禁投） | 为什么坏 | 好例子（可追问 30 分钟不塌） |
|---|---|---|
| "工具调用成功率 94%" | 谁定义"成功"？样本多大？ | "自建 62 条工具调用用例，每周跑一次；工具名解析错误从 11/62 降到 2/62，复现命令见 README" |
| "日均处理 500+ 会话" | 500 从哪数的？含压测吗？ | "生产 7 天真实统计：日均 187 次会话（含 4 个内部账号），峰值 41 次/小时，取自网关日志" |

| 类型 | 错误示例 | 正确做法 |
|---|---|---|
| 空洞 | "负责项目开发工作" | 动词 + 对象 + 结果 |

### 10.3 熟练度分级与 ATS 优化

分级：**精通**=能讲底层原理 + 大量实践 + 能答第三层；**熟悉**=有项目经验、能独立完成；**了解**=学过原理、简单用过。"精通"是负债不是资产——它会把面试官全部火力吸过来。

ATS 五条：① 纯文本友好排版（少图标/图片/多栏/文本框）；② 关键词自然出现 2–3 次（技能区一次、项目里一次）；③ 用标准章节名（教育背景/技术技能/项目经历/个人亮点）；④ 投 PDF，文件名 `姓名-岗位-联系方式.pdf`；⑤ 别把关键词塞进白色字体——ATS 能读出来，人也能。

## 附录 B：进阶理解（为什么简历里的数字要经得起审计）

**1. 简历的读者不是 HR，是那个要和你共事三年的人。** HR 只做关键词匹配，决定你过不过的是未来同事。他读简历的方式是"找漏洞"：看到 94%，第一反应是"我面过十个说 94% 的，九个说不清口径"。**能被审计的数字比漂亮的数字值钱。**

**2. 为什么 star 数是最差的技术论据？** 它同时具备三个缺点：会变（今天 37K、明天 40K，面试官一查就发现你在背旧文）、与技术质量无稳定关系（运营和发布时间影响远大于代码）、不可归因（你说不清其中有多少来自你的贡献）。可替代的硬指标都在仓库里：文件数、行数、测试行数、发布节奏。

**3. 为什么"精通"是负债？** 简历上的词是**提问指令**。"精通 Python"意味着面试官可以随便挑 CPython 实现细节；"熟悉 Python"意味着他会问项目用法。你说"精通"却答不上 GIL 与 asyncio 的关系，损失的不只是这一题，而是**整份简历的可信度**。

**4. 为什么模板要按岗位分，而不是按项目分？** 因为面试是岗位导向的：同一个项目，投 Agent 岗要讲"我怎么改循环"，投平台岗要讲"我怎么接渠道"，投算法岗要讲"我怎么证明它变好了"。按项目分的模板会逼你用一套话术打三个岗位。

**5. 为什么"占位"比"编造"安全？** 编造的数字只有两个结局：侥幸过关（入职后要一直维护这个谎），或被挖穿（当场出局）。占位符的结局只有一个：你迟早要把它填成真的。**把"填不出真数字"当信号**——它说明项目还没做完，该补的是项目，不是文案。

**6. 为什么本章坚持写行号？** 因为行号让说法**可反驳**。你按 `nanobot/agent/loop.py:403` 翻过去看到 `_session_locks`，就说明我没瞎写；对不上就说明文档过期了。一份"不可反驳"的简历碰上一个只信证据的面试官，输的永远是前者。

## 附录 C：Markdown 表格与量化表达

### C.1 表格语法与三条纪律

写指标对比时用三线表：表头 `| 指标 | 改前 | 改后 | 口径 |`，分隔行 `|---|---|---|---|`，然后一行一个指标（如 `| 工具名解析错误 | 11/62 | 2/62 | 同一套 62 条用例 |`）。纪律：① **每张表必须有"口径"列**，没有口径的表格等于没有表格；② 单元格里的竖线要转义成 `\|`；③ 数字右对齐、单位写在表头（`P50 首字（秒）`），不要每个格子写一遍单位。

### C.2 数字的三件套：分子分母、时间窗、测量方式

| 写法 | 缺什么 | 补全后 |
|---|---|---|
| "成功率 94%" | 三样都缺 | "62 条用例中 58 条通过（2026-09 第 2 周，固定模型版本）" |
| "成本降 25%" | 基线与时间 | "2026-08 与 2026-09 两个完整月账单对比，同一价目表，流量持平" |
| "响应 3.2s" | 分位数 | "P50 首字 1.4s，P95 完整回复 6.8s，n=1200" |

写不出三件套时退化成定性描述：**"从'经常误选工具'变成'偶尔误选'"比"准确率 94%"安全一百倍**。

### C.3 动词层级与占位符规范

| 层级 | 动词 | 面试官的理解 |
|---|---|---|
| 主导 | 设计、架构、主导、规划 | 你定方向 |
| 执行 | 实现、开发、集成、搭建、迁移 | 你落地 |
| 辅助 | 参与、协助、配合 | 你打下手 |
| 优化 | 优化、重构、治理、降本 | 你懂度量 |

同一件事可以用不同层级写，但层级必须与真实角色一致。把"参与"写成"主导"，二面必翻车。

| 占位写法 | 含义 | 什么时候用 |
|---|---|---|
| `[占位]` | 必须替换掉的数字/名词 | 所有模板里 |
| `[占位: N]` | 需要填一个数字 | 数量类 |
| `XX%` | 旧模板的坏习惯 | **不要用**（会被误当真实数据投出去） |

投递前全局搜 `[` 与 `占位` 两个字符串，确认零命中。

### C.4 十行脚本自查关键词覆盖率

写十行脚本统计"JD 要但我没有"的词：读两份文本并 `lower()` 归一，用 `kws = ["python","agent","mcp","rag","asyncio"]` 之类列表逐词判断 `if kw in jd and kw not in resume: print(...)`，只打印缺失项。它的价值不在代码，而在"**先定口径再统计**"的习惯——`lower()` 是口径、`kws` 列表也是口径，两者都要能解释给面试官听。
